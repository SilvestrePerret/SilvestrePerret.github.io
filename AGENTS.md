# Coding Agent Guide

## Scope

- Focus on site implementation, maintenance, and interactive widgets. Do not rewrite article prose unless explicitly asked.
- Keep changes narrow and preserve the personal site's existing visual language and content structure.
- See [README.md](README.md) for the project's purpose and AstroPaper origin.

## Commands

- Install and run commands with `pnpm`.
- Start development with `pnpm dev`.
- Run `pnpm lint` and `pnpm format:check` for routine validation.
- Run `pnpm build` before finishing changes that affect rendering, routing, content loading, or production output. It runs `astro check`, builds the static site, generates Pagefind data, and copies that data to `public/pagefind/`.
- Use `pnpm sync` after changing content collections or other Astro-generated types.
- There is no automated test suite. Prefer the narrow checks above, then manually exercise changed interactive behavior when relevant.

## Architecture

- This is a statically generated Astro 5 site. Use `.astro` components for static or server-rendered UI and React only when a widget needs client-side state or lifecycle behavior.
- React components must be hydrated from Astro or MDX with the least eager suitable `client:*` directive. Existing examples are in [src/data/blog/power-laws.mdx](src/data/blog/power-laws.mdx).
- Markdown is for static posts; MDX is for posts that embed components or custom markup. Blog collection rules and frontmatter types live in [src/content.config.ts](src/content.config.ts).
- Shared page chrome belongs in [src/layouts](src/layouts) and [src/components](src/components). Site-wide settings belong in [src/config.ts](src/config.ts); social and sharing links belong in [src/constants.ts](src/constants.ts).
- Post URLs are derived from file paths, not frontmatter slugs. Preserve the routing logic in [src/utils/getPath.ts](src/utils/getPath.ts) and [src/utils/slugify.ts](src/utils/slugify.ts).

## Conventions

- Use the `@/` alias for imports within `src`.
- Follow strict TypeScript and existing Astro/React patterns. Do not leave `console.*` calls; ESLint treats them as errors.
- Use Tailwind CSS v4 utilities and the existing tokens in [src/styles/global.css](src/styles/global.css). Put article-content typography rules in [src/styles/typography.css](src/styles/typography.css).
- Preserve the CSS-variable theme model. Use the configured `dark:` variant rather than introducing a separate theme mechanism.
- Import local SVG icons as Astro components. Use Astro's `Image` component for optimized images where practical.
- Keep browser-heavy libraries and client JavaScript out of static components unless the feature requires them.

## Generated Files

- Do not hand-edit `dist/`, `.astro/`, or `public/pagefind/`.
- `public/pagefind/` is regenerated by `pnpm build`; changes there are build artifacts, not source changes.
